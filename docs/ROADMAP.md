# Roadmap

## M0 — Prove the engine

- [x] Repository/bootstrap design
- [x] Shared core types
- [x] Deterministic daily selector
- [x] Timeline mechanic playable
- [ ] Map mechanic playable
- [x] Internet Timeline experimental game
- [ ] Where Was It experimental game
- [ ] Local progress + streak
- [x] Result/share card baseline
- [ ] `Built with DailyFoundry` attribution/share hook
- [ ] Static production deployment
- [ ] Creator path documented
- [ ] New game pack can be built in <30 minutes

### Explicitly out of scope
Accounts, global leaderboard, comments, likes, following, payments, creator dashboard, workshop, marketplace, mobile app.

## M1 — Product validation

Measure completion, D1/D7 return, share rate, referrals and sessions/player. Players remain frictionless and free during validation.

The public experiments exist to prove repeat play and distribution before we add commercial complexity.

## M2 — Creator validation

Goal: strangers create.

- validation CLI/template/preview workflow
- first 10 external creators
- validate demand for an optional official managed-hosting/convenience layer

Creator-facing engine/game tooling remains public. Hosted-service implementation and commercial operations remain private.

## M3 — Workshop

Only after creator demand is demonstrated: create, publish, play, remix/fork, discovery and moderation.

Public protocols/schemas should allow community participation; official platform operations, ranking systems, managed services and monetization infrastructure may remain proprietary.

## Commercial principle

The engine and player growth loop are not paywalled. Long-term revenue is expected primarily from optional creator/organization convenience and hosted services, with advertising on sufficiently large first-party/hosted player traffic as a possible secondary line.

Detailed pricing, growth experiments and proprietary commercial implementation do not belong in this public repository.
